## Areas checked with no additional finding

The following conclusions are limited to the inspected paths and exclude the findings above.

- **Tenant access and roles:** Workspace API entry points use the access helpers, scope connection lookups to the workspace, and conceal nonmember resources with 404. AI management is owner-restricted. Explicit route selection and execution check role eligibility; execution rereads membership and credentials for each attempt.
- **Platform-admin boundary:** Platform authorization is separate from workspace ownership and beta allowlists. Inspected checks require cookie authentication, current admin membership, verified email, verified TOTP and bounded session age. Step-up is session-bound and expires; TOTP replay protection is present. Bootstrap uses serialized, single-use challenges and a persistent completion marker.
- **Secret-request protection:** Platform mutations enforce origin, session-bound CSRF, bounded bodies, step-up and shared rate limits. Workspace OAuth-app mutations enforce owner access, origin and bounded bodies. This does not certify uniform controls on every application endpoint.
- **Crypto structure:** The v2 parser validates envelope structure, encoding and cryptographic field lengths. AAD binds records to their scope, owner, provider and purpose. Platform and workspace key rings are separated. The inspected legacy-v1 path requires an explicit legacy marker; migrated/new credential records do not automatically downgrade.
- **Credential projections and environment use:** Inspected projections omit secret values and ciphertext. Short-secret hints are suppressed. Secret inputs use the dedicated uncontrolled input path. Runtime provider credentials are resolved from database records; the inspected tenant paths do not fall back to provider environment keys. Environment import is explicit and recorded.
- **SSRF and transport:** Provider destinations are registry-controlled, supplied fields are constrained, arbitrary base URLs are rejected, and test overrides are environment-gated. AI/OAuth credential requests disable redirects. Egress performs address checks during connection resolution, with response-size, timeout and cancellation controls.
- **OAuth binding and refresh:** State is hashed, single-use, session-bound and associated with the workspace, provider and issuing app. Refresh resolves the issuing app rather than a new default. Refresh fencing and the distinct `invalid_client` handling address the earlier blanket-expiry problem; CXH-01 and CXH-14 remain separate gaps.
- **Routing safeguards:** The inspected fallback error classification excludes auth refusal, revocation, safety refusal, cancellation and budget failure. Privacy checks refuse unsuitable/unknown routes. Owner-entered zero prices do not independently establish verified-free status. Ordinary concurrent reservations serialize on the workspace row.
- **Retries and tools:** Normal model retries return proposals only from a successful attempt; tool execution occurs afterward. Retry counts and waits are bounded, the circuit breaker uses persisted attempts, and failed streamed attempts emit discard events. Recovery and malformed-stream gaps are listed above.
- **Migration intent and UI evidence labels:** Migrations `0012`–`0014` add the relevant storage and binding fields, explicitly mark legacy crypto and remove pending authorization states. Legacy local-provider configuration has explicit refusal paths rather than silent cloud conversion. OAuth backfill requires operator-supplied provenance. Provider documentation distinguishes implementation/contract evidence from live checks marked **NOT RUN**.
