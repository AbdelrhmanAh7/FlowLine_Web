# Flowline Phase 2 — agent-driven exploratory test

**Revision:** `d86d1d497304ec9c21d6a3dfbd4cf7f9359c15c0` (`codex-p2`)

**Result:** 14 journeys attempted: **10 PASS, 3 FAIL, 1 BLOCKED**. Product code was not changed or committed.

## Environment and method

- Windows; Node `25.6.1`, pnpm `10.32.1`, `@playwright/test` `1.63.0`, headless Chromium `153.0.8010.12`, Next `16.3.6`.
- Browser target: `http://localhost:3100`; the brief identifies it as the isolated `FLOWLINE_ENV=test` / `flowline_test` stack. I did not inspect its runtime environment or database directly. Fake SaaS and AI/pricing endpoints were at `127.0.0.1:4010` and `:4011`.
- Used one Chromium browser at a time, with UI clicks, typing, dragging, keyboard input, and two browser contexts for tenancy. The only direct requests used for test manipulation were the brief's provider fault/revoke controls; provider state was read only. Health requests diagnosed stack availability. No DB edits or product API setup calls were used.
- Two test workspaces/accounts were created through sign-up and onboarding. One additional sign-up retry reached onboarding during the first outage. I observed numbered runs `#1`–`#32`; 16 side-effect-free HTTP runs were started specifically to exercise pagination. Screenshots, redacted text evidence, and sanitized Playwright traces are in this directory.

## Worked and not tested

The core flow, template, provider fault recovery, automatic lost-response verification, approval decisions, cancel, publish, connection repair, tenancy, responsive layouts, and offline editing all produced real UI and fake-provider effects. Dashboard counts matched the UI-created run history at the captured point; I did not observe a fabricated success or metric.

Viewer approval was unavailable because the product explicitly disables member invitations/roles. The queue limit could not be driven past the UI's concurrency gate. Incoming webhook signature verification, real SaaS accounts, and the complete set of controls/payload fields were outside the permitted UI-only and fake-provider test path. Intermittent session/database outages interrupted several attempts; successful retests and the remaining coverage are recorded above. CX2-01 and CX2-02 should be retested after the stack/session error is fixed.
