- Windows; Node `25.6.1`, pnpm `10.32.1`, Playwright `1.63.0` with headless Chromium, Next `16.3.6`.
- Tested `http://localhost:3100`, the brief's already-running TEST stack, using fresh `@flowline-e2e.test` accounts created through sign-up. Fake SaaS/AI boundaries were the brief's `127.0.0.1:4010` and `:4011` services. I did not inspect the stack's environment or database directly.

Direct calls were limited to the permitted fake-provider fault/revoke controls, read-only fake-provider state and health checks, plus the brief's second-client `POST /api/flows/<id>/runs` queue probe. No server, worker or Docker process was started or stopped.

- Primary evidence is the [completed pass](evidence/retest-complete.json), [outage](evidence/retest-outage.json), [health timeline](evidence/retest-health.txt), [pagination](evidence/retest-pagination.json), and [OAuth hint](evidence/retest-google-hint.json). ## Coverage and evidence handling

The viewer approval check was blocked by the Phase 3 role UI. The database failover implementation and server stdout were not directly observable with the allowed test controls; the retest measured the user-visible outage, health response time and subsequent recovery. The fake OAuth provider auto-approves, so Google account preselection was verified from the UI-initiated start response's `login_hint`, without retaining the OAuth URL.

An initial Playwright trace captured a session cookie and a one-time webhook signing secret, so it was cleared rather than retained as evidence. The report relies on screenshots and redacted event files; the empty `traces/retest-full.zip` is not a usable trace. The generated evidence contains no stored password, cookie or webhook secret. Script assertion errors from intermediate runs were corrected and are not counted as product failures. No full project lint/typecheck/test gate was run because this was an independent browser retest with no product-code changes.
