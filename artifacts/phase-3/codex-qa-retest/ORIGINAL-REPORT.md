# Flowline Phase 3 — agent-driven exploratory browser test

**Status:** Independent staging test, not human UAT. Product code was not changed and nothing was committed. Tested `flowline:ee265ea` at `http://localhost:3200` on 2026-09-28. The read-only health endpoint reported revision `ee265eafe43246d48c3665dd3614fa0ed37c1914`, schema 7, `db: ok`, and `worker: ok`.

## Environment and coverage

- Tooling: one headless Chromium browser (`153.0.8010.12`) controlled with Playwright `1.63.0` through [browser-repl.cjs](scripts/browser-repl.cjs); Node `25.6.1`, pnpm `10.32.1`. The browser had separate owner, member, outsider, and keyboard contexts. All account creation, navigation, forms, canvas edits, approvals, and invitations used the UI. Only the UI-created keys called public `/api/v1`; `/api/health` was read-only.
- Accounts created through sign-up UI: `codex-owner-202609280048@flowline-qa.test`, `codex-member-202609280048@flowline-qa.test`, `codex-outsider-202609280048@flowline-qa.test`. The outsider owned a second QA workspace and invited the owner there so the share-copy UI could be exercised.
- Evidence: 47 screenshots in [screenshots](screenshots/), [browser event log](evidence/browser-events.json), [API key status checks](evidence/api-key-checks.json), [viewport measurements](evidence/viewport-checks.json), [targeted test results](evidence/targeted-tests.txt), and the uploaded [Markdown probe](evidence/qa-policy.md). The event log recorded 158 top-level navigations and 10 HTTP failures: eight expected 404s from tenant/removal probes and two expected 400s from invalid SSO and a transient invalid flow name. Ten console errors corresponded to those 4xx responses. No 5xx responses or uncaught page errors were seen.
- **Hydration warnings:** none seen in 158 top-level navigations. No React hydration text appeared in the captured console events.

## Remaining limits

- No SaaS credentials existed to create a verified connection, test connection stripping on share, or perform a live SaaS action. No SSO IdP or billing provider was configured, so their external flows were assessed from code/tests and honest staging UI states.
- Invalid real-model Copilot output prevented approve/removal-confirmation checks. Agent approval recovery and the viewer Approve control were limited by CX3Q-01. The agent's happy-path ASK approval, editor approval, DENY, and injection probes were exercised.
- Staging has production rate limits and no fault-injection API. No fault-injection, provider outage, or exhaustive button/control matrix was run. The route and viewport samples above are evidence for those samples, not a blanket UI acceptance claim.
